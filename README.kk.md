# Kaspi POS Automation

Kaspi Pay API арқылы POS-жүйелер үшін төлемдерді автоматтандыру. Жоба шот-фактуралар жасау, QR-кодтар генерациялау, транзакциялар тарихын қарау және қайтаруларды рәсімдеу үшін серверлік қосымша мен веб-интерфейс ұсынады.

### Мультисаудагер: күйсіз сервер

Сервер **саудагерлердің деректерін мүлдем сақтамайды**. Onboarding кезінде әр саудагерге жеке құрылғы (deviceId, installId, pinHash) және өз ECDSA P-256 кілттер жұбы жасалады, олардың бәрі Kaspi сессиясымен бірге бір шифрланған **credential envelope** ішіне оралады. Конверт шақырушы тарапқа беріледі, ол оны өзінде сақтап, әр сұраныста `X-Kaspi-Credentials` тақырыбында жібереді.

```
   onboarding                    кез келген кейінгі сұраныс
   ──────────                    ─────────────────────────
   POST /api/auth/init           POST /api/qr/create
     → onboardingState             X-Kaspi-Credentials: <конверт>
   POST /api/auth/send-phone           │
     → onboardingState                 ▼
   POST /api/auth/verify-otp     сервер конвертті шешеді, ОСЫ саудагердің
     → credentials  ────────►    кілтімен сұранысқа қол қояды
       (өзіңізде сақтаңыз)       және оны ұмытады
```

Себебі: Kaspi сессияны құрылғы ізіне байлайды. Барлығына ортақ бір кілт болса, екінші саудагердің кіруі біріншісінің сессиясын **ығыстырар** еді (`StatusCode -101001`). Әр саудагерге бөлек құрылғы бұл мәселені шешеді.

Серверде тек `tracked-payments.json` (аяқталмаған төлемдер, әрқайсысы өз конвертімен), `webhook-retries.json`, `webhooks.json` және `logs/` қалады.

> 🔐 Конверт — bearer-құпия: кім оны иеленсе, сол саудагердің атынан әрекет етеді. Пароль ретінде сақтап, тек TLS арқылы жіберіңіз.

### Webhooks

Сервер жасалған QR және invoice төлемдерінің статустарын автоматты түрде бақылайды (әр 3 секунд сайын polling) және статус өзгерген кезде көрсетілген URL-дарға HTTP POST хабарламаларын жібереді.

- 📡 **Оқиғалар:** `payment.success` · `payment.failed` · `payment.expired` · `payment.lost`
- 🏷️ **Атрибуция:** төлем жасау кезінде `merchantRef` (және `orderId`) жіберіңіз — олар payload ішінде өзгеріссіз қайтарылады
- ⚙️ **Баптау:** `webhooks.json` файлы ([`webhooks.example.json`](./webhooks.example.json) қараңыз)
- 🔐 **Қолтаңба:** HMAC SHA-256
- 🔄 **Retry:** өсетін кідіріспен 3 әрекетке дейін

> 📖 Толығырақ — [API құжаттамасында](./docs/API.kk.md#webhooks--хабарламалар).

## Талаптар

## Жылдам бастау

```bash
# 1. Репозиторийді клондау
git clone https://github.com/tapter-dev/kaspi-pos-automation.git
cd kaspi-pos-automation

# 2. Тәуелділіктерді орнату
npm install

# 3. Шифрлау кілтімен .env жасау
echo "TOKEN_SECRET_KEY=$(openssl rand -hex 32)" > .env

# 4. (Қосымша) Вебхуктарды баптау
cp webhooks.example.json webhooks.json
# webhooks.json файлын өз қажеттіліктеріңізге сай өңдеңіз

# 5. Серверді іске қосу
npm start
```

Іске қосу кезінде ешқандай файл жасалмайды: құрылғылар мен кілттер onboarding кезінде әр саудагерге шығарылады және тек клиенттегі конверт ішінде өмір сүреді.

### 1.x нұсқасынан жаңарту

1.x нұсқасында сессия браузерде сақталған, ал құрылғы ортақ болған (`keypair.json` + `device.json`). Жұмыс істеп тұрған саудагерді **SMS арқылы қайта кірмей** (және сессияны ығыстыру қаупінсіз) көшіру үшін:

```bash
# браузерден localStorage['kaspi_session'] мәнін session.json файлына көшіріңіз
npm run mint-credentials -- --from-session ./session.json
```

Скрипт ескі құрылғы мен кілтті алып, олардан конверт құрастырып, оны басып шығарады. Конвертті өз бэкендіңізде сақтаңыз, содан кейін `keypair.json` / `device.json` файлдарын `*.migrated` деп өзгертуге болады.

> ⚠️ `X-Token-SN` / `X-Vtoken-Secret` / `X-Profile-Id` тақырыптары 2.0.0 нұсқасында қолдау таппайды.

## Шифрлау кілтін ротациялау

`TOKEN_SECRET_KEY` — барлық конверттердің мастер-кілті. Оны жоғалту әр саудагер үшін қайта onboarding дегенді білдіреді, сондықтан оны тізім арқылы ауыстырыңыз:

```bash
TOKEN_SECRET_KEYS=<жаңа_hex>,<ескі_hex> npm start
```

Бірінші кілт шифрлайды, барлығы шешуде сыналады. Ескі кілтпен шифрланған конвертті кездестірген сервер қайта шығарылған нұсқасын `X-Kaspi-Credentials-Refresh` тақырыбында қайтарады — клиентке оны бұрынғысының орнына сақтау жеткілікті. Барлық конверттер жаңарғаннан кейін ескі кілтті тізімнен алып тастауға болады.

### Саудагердің құрылғысын ауыстыру

Бөлек скрипт қажет емес: `/api/auth/init` эндпоинтін `X-Kaspi-Credentials` тақырыбы **жоқ** күйде шақырып, SMS-кіруден қайта өтіңіз — жаңа құрылғы шығарылады. Бұл осы саудагердің Kaspi-дегі ағымдағы сессиясын ығыстыратынын ескеріңіз.

## Демо-интерфейс (`public/`)

`public/` қалтасында серверімен бірге автоматты түрде іске қосылатын және `http://localhost:3000` мекенжайы бойынша қолжетімді кірістірілген веб-интерфейс (SPA) орналасқан.

**Интерфейс мүмкіндіктері:**

- 🔐 **Авторизация** — Kaspi Pay кассирінің телефон нөмірі арқылы 3 қадамды SMS-flow арқылы кіру (нөмірді енгізу → OTP-код → аяқтау)
- 🧾 **Шот жасау** — клиенттің телефон нөмірі бойынша сома мен түсініктемені көрсете отырып шот жасау
- 📱 **QR-төлем** — нақты уақытта статусты бақылаумен төлем үшін QR-код генерациялау
- 📋 **Операциялар тарихы** — транзакциялар тізімін толық мәліметтерімен қарау
- 💰 **Сатылымдар мен қайтарулар** — сатылым статистикасы және қайтаруларды рәсімдеу

**Файлдар:**

| Файл | Сипаттама |
| --- | --- |
| `public/index.html` | HTML-белгілеу және интерфейс стильдері |
| `public/app.js` | Клиенттік логика (API-шақырулар, күй басқару) |

> Интерфейс API-ді көрсету және тестілеу үшін арналған. Продакшн үшін өз фронтендіңізді пайдалану ұсынылады.

## Бірыңғай QR — басқа банктерден төлемдерді қабылдау

`/api/qr/create` арқылы QR-код жасаған кезде жауапта екі өріс қайтарылады:

- **`QrToken`** — `https://pay.kaspi.kz/pay/...` түріндегі сілтеме, тек Kaspi қосымшасында жұмыс істейді.
- **`QrOriginalToken`** — `https://qr.kaspi.kz/...` түріндегі түпнұсқа сілтеме, **Бірыңғай QR** арқылы төлемді қолдайды (басқа банктердің қосымшалары).

Клиенттер басқа банктердің қосымшалары арқылы төлей алуы үшін QR-кодты `QrToken` емес, **`QrOriginalToken`** мәнінен генерациялаңыз.
